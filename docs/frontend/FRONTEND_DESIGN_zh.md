# SSHFerry 前端设计指南

**中文** | [English](FRONTEND_DESIGN.md)

## 设计目标

前端必须保留 SSHFerry 作为“桌面化传输工作区”的产品气质，不能被简化成一个普通网页文件管理器。

## 必须保留的产品结构

- 左侧：站点与会话控制区
- 中间：本地文件浏览区
- 右侧：多个远端面板并排工作区
- 底部：任务中心，并为日志预留位置

这个结构比表面上的“现代化样式”更重要。

## 交互原则

- 任务状态必须足够明显。
- 文件操作要高密度但不混乱。
- 优先使用显式控制，而不是隐藏手势。
- 拖拽必须是一等工作流，而不是附属能力。
- 破坏性操作必须有清晰确认。

## 视觉方向

- 风格：工业化桌面工具，而不是 SaaS 仪表盘
- 密度：信息丰富，但保持可读
- 颜色：平稳中性色 + 清晰状态强调色
- 字体：专业无衬线 + 路径和 ID 使用等宽字体
- 动效：少量、结构化、有明确目的

## Phase 1 必需能力

- 站点管理
- 基础 SSH 命令快速导入
- 本地文件浏览
- 多远端会话并排工作
- 本地到远端、远端到本地、远端到远端拖拽传输
- 具备实时状态与控制动作的任务中心

## Phase 1 非目标

- 装饰性首页视觉
- 单远端面板式布局
- 大量以动画为主的界面表现
- 复杂冲突处理向导
- 用“可观测性控制台”替代任务优先的主结构

## 设计评审清单

- 用户能否一眼看出“站点 + 本地 + 多远端 + 任务”的工作结构？
- 界面是否仍然适合高频重复文件传输操作？
- 任务失败原因和当前传输对象是否容易查看？
- 破坏性操作是否足够明确且不容易误触？
